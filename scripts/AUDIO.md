# Озвучка через Soniox

Скрипт обрабатывает выбранные уроки в `public/translations`.
Для каждого урока читает `tasks.json` и сохраняет записи в подпапку `audio` рядом с ним.
Папка создается автоматически. Имена берутся из `id`: `audio/tasks_001_en.m4a`,
`audio/tasks_001_ru.m4a` и так далее. Номер дополняется нулями минимум до трех цифр:
`001`, `012`, `123`, `1234`.

Формат задания:

```json
{
  "id": 1,
  "ru": { "text": "У меня есть зонт", "audio": true },
  "en": { "text": "I have an umbrella", "audio": false }
}
```

`audio` показывает наличие непустого `audio/tasks_<id из трех цифр>_<язык>.m4a`
относительно папки с `tasks.json`.
Перед генерацией скрипт сверяет флаги обоих языков выбранных уроков с файлами:
для существующих ставит `true`, для отсутствующих или пустых — `false`.
После сохранения каждого аудиофайла сразу записывает `audio: true` в JSON.
При ошибке уже записанный прогресс сохраняется. В режиме `--dry-run` JSON не меняется.

Нужен Node.js 20.6+.

## Ключ и голоса

В корне проекта уже создан локальный файл `.env.soniox.local`.
Вставьте ключ после знака `=`:

```dotenv
SONIOX_API_KEY=ваш_ключ
SONIOX_VOICE_EN=Adrian
SONIOX_VOICE_RU=Adrian
```

Этот файл исключен из Git правилом `*.local`. Для нового checkout скопируйте
`.env.soniox.example` в `.env.soniox.local`. Переменные уже установленного окружения
имеют приоритет над файлом. Не используйте префикс `VITE_` для ключа.

Голос Adrian выбран как начальная настройка. Для смены голоса скопируйте его имя
из Soniox Console → Text-to-speech → Voices в нужную переменную.

## Запуск из корня проекта

Один урок (аргумент — путь относительно `public/translations`):

```powershell
npm run audio:generate -- "express/A0 1-2"
```

Все уроки Express уровня A0:

```powershell
npm run audio:generate -- "express/A0*"
```

Несколько уроков или шаблонов:

```powershell
npm run audio:generate -- "express/A0*" "express/A1 1-2" "titan/1"
```

Все уроки обоих курсов:

```powershell
npm run audio:generate -- --all
```

Создать не больше двух новых файлов суммарно для всех выбранных уроков:

```powershell
npm run audio:generate -- "express/A0*" --limit 2
```

Только английские версии:

```powershell
npm run audio:generate -- --all --languages en --limit 10
```

По умолчанию запросы выполняются последовательно (`--concurrency 1`).
Для четырех параллельных запросов укажите:

```powershell
npm run audio:generate -- "express/*" --concurrency 4
```

Значение должно быть целым положительным числом.

Шаблоны заключайте в кавычки, чтобы `*` обрабатывал сам скрипт.
Звездочка обозначает произвольную часть имени внутри одного сегмента пути:
`express/A0*`, `express/*`, `titan/*`, `*/*`. При отсутствии совпадений скрипт
завершается с ошибкой до генерации. Повторные совпадения не дублируют уроки.
Уроки обрабатываются в порядке имен с учетом чисел: `1-2` раньше `11-12`.
`--all` нельзя сочетать с шаблонами. Без выбора уроков сохраняется прежнее
поведение: обрабатывается только `express/A0 1-2`.

`--limit` ограничивает число **новых выходных файлов за весь запуск**, а не заданий,
уроков. Готовые файлы пропускаются и не расходуют лимит.
Для каждого недостающего файла выполняется отдельный запрос к Soniox, даже если
текст совпадает с другим заданием. Без `--limit` обрабатываются
все недостающие файлы. План показывает пропуски, число файлов к созданию и остаток
за пределами лимита.
Все запуски без `--dry-run` могут расходовать баланс Soniox.

## Формат и повторные запуски

Скрипт использует модель `tts-rt-v2`, AAC 64 кбит/с, 24 кГц.
Soniox возвращает готовый M4A; скрипт сохраняет его байты напрямую.
Ответ может иметь тип `audio/*` или `application/octet-stream`: Soniox также
возвращает AAC уже в контейнере MP4 с общим бинарным типом. Скрипт принимает оба
варианта.

Число одновременных запросов задается через `--concurrency` (по умолчанию 1).
Запись `tasks.json` одного урока выполняется последовательно, чтобы результаты
параллельных запросов не конфликтовали. Строки `ready` появляются в порядке завершения,
счетчик показывает число сохраненных результатов за текущий запуск.
Скрипт проверяет только конечные файлы
в подпапке `audio` рядом с `tasks.json`. Существующие непустые `.m4a` пропускаются без запросов к API,
в том числе при изменении текста или голоса. Нулевые файлы
считаются незавершенными и создаются заново. Для обновления конкретной озвучки
удалите соответствующий `.m4a` и повторите команду: будет сделан новый запрос.
Отдельного кэша нет. Оставшаяся от прежней версии папка `.soniox-cache/` больше
не используется.

При блокировке файла (`EPERM`, `EACCES`, `EBUSY`) во время сохранения скрипт
ждет освобождения файла и повторяет только операцию с диском. Пауза растет от 100 мс
до 5 секунд; ограничения на число попыток нет. Полученное аудио остается в памяти,
повторный платный запрос не отправляется. Сообщение об ожидании появляется сразу
и затем не чаще раза в минуту. После освобождения файла работа продолжается автоматически.
Если доступ запрещен постоянно, нужно исправить права или остановить скрипт через `Ctrl+C`.
`tasks.json` по-прежнему заменяется через временный файл; прежний JSON не удаляется.

При других ошибках скрипт перестает брать новые задания, дожидается уже отправленных запросов
и сохраняет их успешные результаты, затем завершается с ошибкой.
После устранения причины запустите ту же
команду: успешно созданные конечные файлы будут пропущены. Если запрос
оборвался до сохранения ответа, повторный запуск может привести к повторному
списанию. Автоматических повторов запросов нет.

Проверки без обращения к Soniox (используют сохраненную тестовую аудиозапись):

```powershell
npm run audio:test
```

Документация: [REST API](https://docs.soniox.com/tts/rest-api/generate-speech),
[форматы](https://docs.soniox.com/tts/concepts/audio-formats),
[голоса](https://docs.soniox.com/tts/concepts/voices).

## Импорт фраз из записей уроков

Скрипт `import-lesson-audio.py` читает английские фразы из `tasks.json`, ищет их
на дорожке с начиткой урока и нарезает по паузам. Затем локальный Whisper
распознаёт полученные M4A без подсказок из заданий. Скрипт сверяет слова, игнорируя
регистр и пунктуацию. При запуске с `--apply` он устанавливает подтверждённые
файлы `tasks_*_en.m4a` и проставляет `en.audio: true` там, где запись добавилась.

Из корня проекта в PowerShell:

```powershell
python -m venv .lesson-audio-cache/venv
& .lesson-audio-cache/venv/Scripts/python.exe -m pip install faster-whisper==1.2.1 av==16.1.0 num2words==0.5.14
& .lesson-audio-cache/venv/Scripts/python.exe -X utf8 scripts/import-lesson-audio.py 'express/A0 1-2'
& .lesson-audio-cache/venv/Scripts/python.exe -X utf8 scripts/import-lesson-audio.py 'express/A0 1-2' --apply
```

Без `--apply` скрипт сохраняет фрагменты и `report.json` в `.lesson-audio-cache/`.
Отчёт содержит исходный файл, текст задания, результат распознавания
подтверждённой фразы и её границы в исходнике. Повторный запуск использует
сохранённые результаты для той же модели, исходника и текста заданий.
Первый запуск скачивает модель `large-v3-turbo`. Аудио обрабатывается локально.

Без аргументов скрипт обходит все уроки «Экспресса» и «Титанового». Можно передать
несколько уроков или шаблонов, например `'express/A0*' 'titan/1'`. По умолчанию
записи берутся из `F:\Английский по плейлистам`. Укажите `--source-root`, если
перенесли каталог, или `--source` с путём к MP3 для одного выбранного урока.

Для обработки на NVIDIA используйте `--device cuda`. В Windows при необходимости
передайте `--cuda-dll-dir` с каталогом DLL для CUDA 12 и cuDNN 9. При нехватке
видеопамяти уменьшите `--batch-size`.

Чтобы перепроверить пропуски более крупной моделью, сначала запустите импорт
с `--model base.en`, затем повторите его для тех же уроков с параметрами
`--model large-v3-turbo --fill-gaps-from base.en`. Флаг `--equivalent-spellings`
разрешает отдельные британские и американские написания, запись целых чисел
цифрами и обозначения валют. При повторном запуске `--retry-unverified`
перепроверяет только пропуски в сохранённом отчёте.
`--report .lesson-audio-cache/summary.json` сохраняет сводку и список фраз,
для которых проверка не нашла подходящей записи.

## Постоянное усиление для урока

`normalize-lesson-gain.py` сначала измеряет громкость и максимальный истинный пик
всех английских фраз каждого урока. Он рассчитывает одно постоянное усиление
для урока с целевой громкостью −16 LUFS и запасом до пика −1,5 dBTP.
Усиление ограничивается самым высоким пиком урока. Если безопасного запаса нет,
скрипт сохраняет исходные файлы. Прибавки меньше 0,25 dB также пропускаются.

Запуск из корня проекта требует установленного окружения импорта и FFmpeg:

```powershell
& .lesson-audio-cache/venv/Scripts/python.exe scripts/normalize-lesson-gain.py plan
& .lesson-audio-cache/venv/Scripts/python.exe scripts/normalize-lesson-gain.py apply
```

Можно указать урок или шаблон после `plan` и `apply`, например `'express/A2 21-22'`.
Перед обработкой сохраняются побайтовые копии в
`.lesson-audio-cache/lesson-gain/<курс>/<урок>/originals` и план `plan.json`.
Фрагменты с усилением кодируются в AAC 128 кбит/с. Проверка пиков выполняется
после кодирования. Если нужен дополнительный запас, усиление уменьшается одинаково
для всех фраз урока. Завершённые уроки повторный запуск сверяет по контрольным суммам.

## Усиление с ограничением коротких пиков

Текущий вариант обработки использует `normalize-lesson-limited.py`. Для каждого
урока он рассчитывает постоянную прибавку до −19 LUFS по измерению исходных записей.
Ограничитель пиков настроен как в прослушанном примере B1 5–6: `limit=0.794`,
`level=false`, `attack=5`, `release=50`, `latency=true`. Если пики после AAC-кодирования
превышают −1 dBTP, порог ограничителя уменьшается одинаково для всего урока.
Прибавка не пересчитывается по отдельным фразам. Уроки, исходно громче целевого
уровня, сохраняются из резервных копий без усиления.

```powershell
& .lesson-audio-cache/venv/Scripts/python.exe scripts/normalize-lesson-limited.py
```

Команда использует исходники и измерения из `lesson-gain`, полученные предыдущим
шагом `normalize-lesson-gain.py plan`. Можно передать уроки или шаблоны, например
`'express/B1 5-6'`. Текущие планы, контрольные суммы и итоговые измерения сохраняются
в `.lesson-audio-cache/lesson-limited/`. Исходные резервные копии остаются в
`.lesson-audio-cache/lesson-gain/<курс>/<урок>/originals/`.

## Озвучка словарей из исходных записей

`scripts/import-words-audio.py` находит записи словарей «Титанового» по номеру
урока и имени (`Lesson … new words.mp3`, `…w.mp3` или `…в.mp3`). До нарезки
он измеряет громкость всей записи и применяет единое усиление до −19 LUFS и
ограничитель пиков с настройками из `normalize-lesson-limited.py`. Слова
сопоставляются с `words.json` и независимо проверяются распознаванием нарезанных
фрагментов. Подтверждённые фрагменты сохраняются в `audio/words_001_en.m4a` и отмечаются
как `en.audio: true`. Если распознавание не подтвердило отдельные слова,
`scripts/fill-words-audio.py --apply` нарезает пропуски по их порядку в словаре,
попадающим между соседними найденными фрагментами, и паузам в записи. Для B1
он также исключает вступительное объявление номера урока. Существующие файлы
скрипты не перезаписывают.

```powershell
& .lesson-audio-cache/venv/Scripts/python.exe -X utf8 scripts/import-words-audio.py
& .lesson-audio-cache/venv/Scripts/python.exe -X utf8 scripts/import-words-audio.py 62 151
```

Нужны FFmpeg и окружение из раздела «Импорт фраз из записей уроков». По умолчанию
используется локальная модель `.lesson-audio-cache/models/base.en`; её можно
изменить параметром `--model`. Исходную папку можно изменить через `--source-root`.
Результаты проверки и временные фрагменты сохраняются в `.lesson-audio-cache/words-audio/`;
повторный запуск использует кэш при неизменных исходнике и словаре. В
`report.json` каждого урока есть границы и статус всех слов.

Чтобы заполнить пропуски по порядку слов, затем проверить истинные пики готовых AAC-файлов:

```powershell
& .lesson-audio-cache/venv/Scripts/python.exe -X utf8 scripts/fill-words-audio.py --apply
& .lesson-audio-cache/venv/Scripts/python.exe -X utf8 scripts/check-words-audio-peaks.py
```

Если пик превышает −1 dBTP, проверка повторно нормализует исходную запись с
более строгим ограничением и пересоздаёт фрагменты по сохранённым границам.
Перед заменой сверяются контрольные суммы файлов.

Для повторной проверки пропусков другой локальной моделью выполните сначала
`& .lesson-audio-cache/venv/Scripts/python.exe -X utf8 scripts/retry-words-audio.py`,
затем снова запустите проверку пиков. По умолчанию используется модель `small.en`;
параметром `--model` можно выбрать другую.
