# Озвучка через Soniox

Скрипт обрабатывает выбранные уроки в `public/translations`.
Для каждого урока читает `tasks.json` и сохраняет записи в подпапку `audio` рядом с ним.
Папка создается автоматически. Имена берутся из `id`: `audio/001_en.m4a`,
`audio/001_ru.m4a` и так далее. Номер дополняется нулями минимум до трех цифр:
`001`, `012`, `123`, `1234`.

Формат задания:

```json
{
  "id": 1,
  "ru": { "text": "У меня есть зонт", "audio": true },
  "en": { "text": "I have an umbrella", "audio": false }
}
```

`audio` показывает наличие непустого `audio/<id из трех цифр>_<язык>.m4a`
относительно папки с `tasks.json`.
Перед генерацией скрипт сверяет флаги обоих языков выбранных уроков с файлами:
для существующих ставит `true`, для отсутствующих или пустых — `false`.
После сохранения каждого аудиофайла сразу записывает `audio: true` в JSON.
При ошибке уже записанный прогресс сохраняется. В режиме `--dry-run` JSON не меняется.

Нужен Node.js 20.6+.

## Ключ и голоса

В корне проекта уже создан локальный файл `.env.soniox.local`.
Вставьте ключ после знака `=`:

```dotenv
SONIOX_API_KEY=ваш_ключ
SONIOX_VOICE_EN=Adrian
SONIOX_VOICE_RU=Adrian
```

Этот файл исключен из Git правилом `*.local`. Для нового checkout скопируйте
`.env.soniox.example` в `.env.soniox.local`. Переменные уже установленного окружения
имеют приоритет над файлом. Не используйте префикс `VITE_` для ключа.

Голос Adrian выбран как начальная настройка. Для смены голоса скопируйте его имя
из Soniox Console → Text-to-speech → Voices в нужную переменную.

## Запуск из корня проекта

Один урок (аргумент — путь относительно `public/translations`):

```powershell
npm run audio:generate -- "express/A0 1-2"
```

Все уроки Express уровня A0:

```powershell
npm run audio:generate -- "express/A0*"
```

Несколько уроков или шаблонов:

```powershell
npm run audio:generate -- "express/A0*" "express/A1 1-2" "titan/1"
```

Все уроки обоих курсов:

```powershell
npm run audio:generate -- --all
```

Создать не больше двух новых файлов суммарно для всех выбранных уроков:

```powershell
npm run audio:generate -- "express/A0*" --limit 2
```

Только английские версии:

```powershell
npm run audio:generate -- --all --languages en --limit 10
```

Шаблоны заключайте в кавычки, чтобы `*` обрабатывал сам скрипт.
Звездочка обозначает произвольную часть имени внутри одного сегмента пути:
`express/A0*`, `express/*`, `titan/*`, `*/*`. При отсутствии совпадений скрипт
завершается с ошибкой до генерации. Повторные совпадения не дублируют уроки.
Уроки обрабатываются в порядке имен с учетом чисел: `1-2` раньше `11-12`.
`--all` нельзя сочетать с шаблонами. Без выбора уроков сохраняется прежнее
поведение: обрабатывается только `express/A0 1-2`.

`--limit` ограничивает число **новых выходных файлов за весь запуск**, а не заданий,
уроков. Готовые файлы пропускаются и не расходуют лимит.
Для каждого недостающего файла выполняется отдельный запрос к Soniox, даже если
текст совпадает с другим заданием. Без `--limit` обрабатываются
все недостающие файлы. План показывает пропуски, число файлов к созданию и остаток
за пределами лимита.
Все запуски без `--dry-run` могут расходовать баланс Soniox.

## Формат и повторные запуски

Скрипт использует модель `tts-rt-v2`, AAC 64 кбит/с, 24 кГц.
Soniox возвращает готовый M4A; скрипт сохраняет его байты напрямую.
Ответ может иметь тип `audio/*` или `application/octet-stream`: Soniox также
возвращает AAC уже в контейнере MP4 с общим бинарным типом. Скрипт принимает оба
варианта.

Запросы выполняются последовательно. Скрипт проверяет только конечные файлы
в подпапке `audio` рядом с `tasks.json`. Существующие непустые `.m4a` пропускаются без запросов к API,
в том числе при изменении текста или голоса. Нулевые файлы
считаются незавершенными и создаются заново. Для обновления конкретной озвучки
удалите соответствующий `.m4a` и повторите команду: будет сделан новый запрос.
Отдельного кэша нет. Оставшаяся от прежней версии папка `.soniox-cache/` больше
не используется.

При ошибке скрипт останавливается. После устранения причины запустите ту же
команду: успешно созданные конечные файлы будут пропущены. Если запрос
оборвался до сохранения ответа, повторный запуск может привести к повторному
списанию. Автоматических повторов запросов нет.

Проверки без обращения к Soniox (используют сохраненную тестовую аудиозапись):

```powershell
npm run audio:test
```

[форматы](https://docs.soniox.com/tts/concepts/audio-formats),
[голоса](https://docs.soniox.com/tts/concepts/voices).
